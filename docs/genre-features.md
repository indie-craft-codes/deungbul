**조사 날짜**: 2026-11-27. 상용 게임의 수치(천장, 초기화 시각, 제재 길이)는 패치로 자주 바뀐다. 틀에 중요한 것은 "어떤 수치냐"보다 "그 수치를 **설정으로 바꿀 수 있어야 한다**"는 점이다.

**원본.** 조사 파일 넷은 저장소 밖(`%TEMP%\dg-work\`)에 있다: `genre-research.md`(장르 1~4, 교차 표 136행), `genre-research-5-7.md`(장르 5~7, 118행), `genre-research-8-11.md`(장르 8~10 99행, 상용 서비스 29행), `engine-inventory.md`(틀의 기능 118개). 임시 폴더는 지워질 수 있으므로 **핵심 수치와 출처 URL은 이 문서에 옮겼다**(2절, 7절, 8절). 틀의 목록은 그 뒤에 더해진 것(판 모듈 `rooms`의 선 돌리기·등수·자리 수 범위·막대 자리·기권 확인·컴퓨터 이름, 새 모듈 `chars`·`morph`, 겉모습 부품)을 [framework-status.md](framework-status.md)와 코드로 확인해 반영했다.

**법률 부분은 법률 자문이 아니다.** 7절은 조사자가 읽은 법조문·해설·보도를 정리한 것이다. 국가법령정보센터 본문은 2026-11-27의 현행본(게임산업법 시행 2025.10.23. 본, 일부 2027.4.21. 시행 예정 개정 포함)이다. 출시 전에는 변호사 검토가 필요하다.

## 3. 통합 교차 표

세 원본 표(136행 + 118행 + 99행)와 상용 서비스 표(29행)를 하나로 합쳤다. 같은 기능의 다른 이름은 하나로 묶었다(예: 장르 1~4의 '끊김 후 재접속'·'재접속 유예 시간', 5~7의 '재접속(세션 복구)', 8~10의 '재접속 시 상태 복원' → c22).

**열.**

- `1`~`10`: 장르 번호(1절 표). 칸은 `필`·`흔`·`일`·`없`.
- **`*` 붙은 칸**: 원본 표에 그 장르의 판정이 없어서, 이 문서를 쓰며 원본 본문(대표 게임 설명)과 장르 성격으로 채운 판단이다 [추정]. 2,380칸 가운데 1,151칸(48%)이다. 별 없는 칸은 원본의 교차 표나 장마다의 기능 표가 판정한 값이다. 원본 행 여럿을 하나로 묶을 때 값이 갈리면 그 장르에서 더 높은 판정을 택했다.
- **상용**: 장르를 가로지르는 상용 요건. `법` = 확인한 법조문 근거가 있다(나라는 7절). `플` = 웹 포털·플랫폼 요건(CrazyGames·Poki·iOS). `관` = 업계 관행상 필수(원본 11장의 '관행 필수'와 장르 1~4 원본의 '장르 공통 필수').
- **우리 틀**: `있음`(완성) / `기초`(돌지만 상용 기대치의 일부) / `흔적`(자리·한두 함수뿐) / `없음`, 그리고 모듈 id·파일. 기준은 2026-11-27의 코드다. `(게임 몫)`은 틀이 아니라 게임이 만들 것이라 빈 곳 점수에서 뺐다.

## 4. 빈 곳 분석

**점수.** 장르마다 `필`=3, `흔`=2, `일`=1, `없`=0을 더한다(최대 30). 상용 열이 `법`이면 +4, `플`이면 +3, `관`이면 +2. 우리 틀이 `있음`인 행과 게임 몫인 행은 뺐다(170행이 남는다). 같은 점수면 `필`이 많은 것, 그다음 `없음` → `흔적` → `기초` 차례.

**점수가 놓치는 것.** `*` 칸이 절반이라 점수는 대강의 순서다. 또 한국 웹 출시와 등불지기의 사정은 점수에 없다: **확률 정보 공개(e6, 21점, 56위)**는 장르 점수가 낮지만 등불지기의 강화 하락에 유료 재료가 붙는 순간 법적 의무가 되므로 5절에서 앞으로 당겼다. 반대로 서버 확장(g10)은 점수가 높지만 지금 규모(300명)에서는 급하지 않다.

**크기**: 작음 = 기존 모듈 안의 칸이나 화면 하나(며칠). 중간 = 새 모듈 하나 또는 저장 칸이 생김. 큼 = 여러 모듈·저장 형식·관리 화면에 걸침.

## 5. 고도화 제안 순서

**지키는 것** ([framework-status.md](framework-status.md)의 원칙과 사용자 결정):
- 새 기능은 시스템 모듈로 넣고, 고르지 않으면 없는 것과 같게 한다. 내용 칸을 적지 않으면 지금과 같다(등불지기·예제의 황금 실행이 바이트까지 같아야 한다).
- 화면 문장은 모두 i18n을 거친다.
- **계정·로그인, 현금 결제, 비용이 드는 외부 서비스는 지금 하지 않는다.** 그 대신 저장 키(지금의 기기 토큰 해시)를 단위로 만들고, 인증·결제·광고는 **갈아 끼우는 접점**만 둔다. 결정이 필요한 것은 아래 5.9에 모았다.

| 묶음 | 이름 | 한 줄 |
|---|---|---|
| 1 | 운영의 바탕 | 시간(초기화)·원격 설정·기능 깃발·공지·점검 |
| 2 | 웹 출시의 바탕 | 탭 대응·설정 창·로딩 예산·오류 수집·약관과 개인정보·튜토리얼·인증과 플랫폼 접점 |
| 3 | 사회와 안전 | 친구·서버 차단·대화 채널·귓말·정해진 문장·금칙어 정규화·연령과 제한 모드 |
| 4 | 확률과 재화의 투명성 | 확률표 단일 원본과 공개 페이지·변경 이력·추첨 기록, 재화 종류, 확인 단계 |
| 5 | 운영 도구와 고객지원 | 분석 이벤트·웹 관리 화면·문의·계정 단위 롤백·봇 의심 점수·경보 |
| 6 | 라이브 콘텐츠 | 이벤트·상점 일반화·주간 임무·시즌과 무료 보상 트랙·우편 만료·업적 |
| 7 | 판의 공통화 | 방 코드·링크·공개 설정·방장·준비·난입과 관전·여러 판 규칙 |
| 8 | 경쟁 | 레이팅·배치·등급과 시즌 초기화·순위표 일반화·큐·이탈 제재·리플레이 |

순서의 까닭: 1은 6·4·8이 기대는 바탕(시각, 바꿀 수 있는 설정)이다. 2는 작고 서로 독립이며 어떤 장르든 공개 웹에 내려면 필요하다(포털 요건). 3은 열 장르 모두의 필수인데 계정 없이 저장 키로 할 수 있다. 4는 법이 걸리고(등불지기 강화 하락) 결제 전에 구조를 잡아야 싸다. 5는 사람이 늘면 바로 필요하고 법(이용자 불만 처리)도 걸린다. 6·7·8은 장르 기능이다. 7은 판 모듈 쪽 작업이 이미 이어지고 있어(카드 게임 검증이 다음 차례) 1~5와 나란히 할 수 있다.

### 5.1 묶음 1 — 운영의 바탕

| 기능 | 표 | 메모 |
|---|---|---|
| 초기화 스케줄러 | d1 | 시간대·하루 시작 시각·주의 시작 요일. 일·주·월 경계 사건 `dayReset`·`weekReset`·`monthReset` |
| 주간·월간 임무 | d2 | `daily`의 임무에 `period: 'day' \| 'week' \| 'month'` |
| 원격 설정 저장소 | d12 | 버전 있는 키-값(SQLite), 관리자 편집, 검증, 되돌리기, 재시작 없이 반영 |
| 기능 깃발·킬 스위치 | d13 | 거래·우편·뽑기·채팅·신규 접속을 끄는 스위치. 모듈이 묻는 `g.flags.on('market')` |
| 공지 | d10 | 예약(시작·끝), 접속 때 창, 흐르는 띠, 다국어 |
| 점검 모드 | d11 | 깃발 하나로 관리자만 입장, 예정 시각 카운트다운, 안내 화면, 끝나면 보상 일괄 우편 |

- **틀 설계 메모**: 시간은 핵심 시스템 `clock`(후보 이름: `engine/server/game/systems/clock.ts`)으로 둔다. 모든 시각은 UTC로 저장하고, 내용 칸 `RESET: { tz, dayAt, weekStart }`를 적지 않으면 지금의 '서버 현지 자정'과 같게 한다(황금 실행 유지). 원격 설정은 핵심 `live`(후보)로: 게임이 **덮어쓸 수 있는 내용 칸을 이름으로 선언**한다(`LIVE_KEYS`: 예 `GACHA_RULES.rates`, 배율, 공지). 선언하지 않은 칸은 소스 컴파일 그대로다. 값은 같은 검증기를 지나야 반영된다(`chardef`의 '믿지 않고 검증' 방식). 공지·점검은 관리자 통로(`net/admin.ts`)의 새 명령과 화면의 `hud/notify.ts`를 쓴다.
- **기존 모듈과의 관계**: `daily`는 `clock`의 사건을 받는다. `gacha` 배너의 `start`·`end`도 같은 시계로. 관리자 CLI 명령에 `notice`·`maint`·`set`·`flag`를 더한다.
- **검증**: 부하 도구의 가상 시계로 일·주·월 경계를 넘기는 시험. 작은 수집형 증명 게임(일일·주간 임무, 기간 배너)을 문서만 보고 만들어 본다. 점검 리허설(예고 → 카운트다운 → 차단 → 해제 → 보상 우편)을 등불지기 복사본에서.

| 파티 저장·파티 찾기 | b4, b5 | 끊겨도 파티 유지, 활동별 모집 |

- **틀 설계 메모**: 대화는 지금 핵심이므로 채널 종류도 핵심에 둔다(`net/server.ts`의 `chat`을 `engine/server/game/systems/chat.ts`로 꺼내는 것이 후보). 친구는 선택 모듈 `friends`(의존 없음), 정해진 문장은 핵심 화면 부품. 차단 목록은 `client/social.ts`의 이름 기준 로컬 저장을 서버의 저장 키 기준으로 옮기고, 이름이 바뀌어도 풀리지 않게 한다. 모든 관계는 저장 키를 단위로 저장하고, 계정이 생기면 키 → 계정 id로 한 번 옮긴다(이전 함수는 `migrate.ts`에).
- **기존 모듈과의 관계**: `party`·`guild`·`rooms`의 초대가 친구 목록을 쓴다. `sanctions`의 말 막기가 모든 채널에 걸린다. `moderation`의 신고가 채널 이름을 기록한다.
- **검증**: 파티 증명 게임(그림·낱말 맞히기: 대화가 곧 답)으로 채널·정해진 문장 모드·차단·신고를 실제 플레이로. 협동 던전 쪽에서는 파티 대화·핑.

### 5.4 묶음 4 — 확률과 재화의 투명성

| 기능 | 표 | 메모 |
|---|---|---|
| 확률표 단일 원본 | e6, e7 | 뽑기·강화·상자·합성이 모두 한 곳의 표에서 굴림 |
| 공개 페이지·변경 이력 | e6 | 게임 안 표, 게임 밖 공개 URL(정적 HTML·JSON), 변경 사전 공지·이력 |
| 추첨 기록 | f16 | 사용자·시각·결과·적용한 표의 버전. 뽑기·강화·거래 내역 화면 |
| 재화 종류 | a24, e4 | 유상·무상·이벤트·귀속, 쓰는 차례(무상 먼저 등), 만료 |
| 귀한 재화 확인 단계 | e16 | 두 단계 확인, 실제 가격을 병기할 칸(결제 뒤 채움) |

- **틀 설계 메모**: 선택 모듈 `odds`(후보, 의존 없음). 표 하나 = `{ id, kind: 'capsule' \| 'enhance' \| 'combine' \| 'ceiling', steps[], pity?, limited?, version }`. `gacha`의 공개 확률표 셈(이미 서버와 같은 셈)을 여기로 옮기고, `gear`의 `ENHANCE` 성공·하락 확률도 이 표에서 읽게 한다(적지 않으면 지금 표 그대로). 공개 페이지는 빌드·시작 때 정적 폴더에 쓰고 원격 설정(묶음 1)으로 표가 바뀌면 다시 쓴다. 추첨 기록은 장부(`ledger.ts`) 옆 표에 쌓는다: 손해배상 다툼에서 사업자가 '과실 없음'을 입증해야 하므로(7절 5번) 보관 기간을 설정으로. 재화 종류는 `CURRENCIES`의 선택 칸이고, 장부의 원인 기록에 종류를 붙인다.
- **왜 결제 전에**: 등불지기의 강화 하락(승인된 경제 방향)은 '강화형 확률형 아이템'에 해당할 수 있다. 강화 재료를 직·간접 유상으로 얻게 하는 순간 공개 의무가 생긴다 [추정: 문체부 해설서 기준]. 매출 1억 원 이하 중소기업 예외에 드는 동안에도 처음부터 같은 구조로 만드는 것이 싸다.
- **검증**: 등불지기 강화와 수집형 뽑기로 시험: 큰 수 굴림의 분포 = 게임 안 표 = 공개 페이지의 값, 표를 바꾸면 이력이 남고 추첨 기록에 새 버전이 찍힘. 단계별 확률(강화 단계마다)과 천장(보정)이 모두 페이지에 나옴.

### 8.12 원본끼리 어긋난 것
- **클래시 오브 클랜 보호막**: 장르 1~4 원본 부록은 "파괴율 30% → 12시간, 마을 수비대"(구 자료), 장르 5~7 원본은 2025-10 개편 뒤 "30% 이상 → 8시간, 마을 경비 폐지". 이 문서는 뒤의 것을 쓴다.
- **Valheim 저장 주기**: 부록의 `-saveinterval 900 -backups 5`는 호스팅 업체의 예시, 공식 기본값은 `1800`·`4`.
- **외부 로그인**: 장르 1~4 표는 수집형·대전에서 '필수'로 보지만 CrazyGames는 외부 로그인을 금지하고 포털 계정을 요구한다. 웹 포털에 낼 때는 포털 계정이 그 자리를 갖는다.
- **재화 다층**: 장르 1~4 표는 네 장르 모두 '필수'지만 Poki는 이중 화폐를 지양한다(광고만 허용, 인앱 결제 금지).
- **원본 안의 어긋남**: LoL 다시 하기 55초/90초, 브롤 랭크 입장 1,000/5,000 트로피, 블루 아카이브 천장 변경 시점, 니케 픽업 비중 1%/2%, 원신 소프트 천장 시작 70~75, Chess.com 재접속 상·하한, DST 스냅샷 5/6개, 헤이 데이 동네 인원·더비 규모, 디아블로 4 거래 규칙, RoK KvK 길이.
- **틀의 목록과 지금의 코드**: 틀 목록 원본은 선택 모듈 23개였으나 지금은 25개(`chars`, `morph`). 원본의 '판 규칙의 자리 수 고정·등수 없음'은 이후 메워졌다(`seats: { min, max }`, 등수 `finish`). 원본이 지적한 문서와 코드의 차이(뿌리 `package.json`에 지운 시제품의 스크립트가 남음 등)는 이 문서가 고치지 않았다.
- **초기화 시각**: 틀의 `daily`는 서버 현지 자정에 초기화한다. 조사(8~11 원본 4.13)는 서머타임 흔들림 때문에 UTC 고정 시각을 권한다. 묶음 1의 기본값을 지금처럼 두고 설정으로 바꾸게 하는 것은 이 때문이다.
