# UI/UX 검토: 세 게임을 플레이어로 해 보고 (2026-11-27)

## 0. 머리말

**왜.** 사용자 말 "UI/UX도 전반적으로 개선해 줘". [screens.md](screens.md)가 장르별 기본 화면(묶음 A~E)을 조사했고, 지금 다른 작업이 묶음 A(화면 쌓기·뒤로·폰 구역 배치·재화 줄·알림 점)와 B(수집형 홈 키트·단계 정보 창·편성 확인·결과 창)를 만들고 있다. 이 문서는 그 **밖의** 것 — 시각 디자인의 일관성, 글자·대비, 누르는 크기, 피드백·연출, 정보 구조와 문장, 빈·오류 상태, 첫 경험, 접근성, 묶음 C~E 범위의 화면, 등불지기의 화면 — 을 **플레이어 입장에서 실제로 해 보고** 적는다. A/B 범위의 문제도 보이면 적되 'A/B에서 다룰 것'으로 표시한다.

**어떻게 했나.** 저장소 d21d96b를 클론해 빌드하고 임시 서버(등불지기 3017, 예제 3018, 메아리 계약 3021, DB는 클론의 `tmp/`)를 띄웠다. 헤드리스 Chrome(GPU)으로 아이폰 세로 390×844(터치·`pointer: coarse`·안전 영역 위 47/아래 34 흉내)·가로 844×390(안전 영역 좌우 47/아래 21), PC 1280×720·1920×1080, 한국어·영어에서 처음 접속부터 놀았다: 메아리 계약은 직업 고르기 → 튜토리얼 → 1-1~1-4 전투·결과 → 뽑기 → 메뉴 탭 열다섯 → 울림골 → 다시 탑(약 25분), 등불지기는 직업 고르기 → 자동 사냥 → 메뉴 탭 아홉 → 가방·지도·도감 → 퀘스트 따라 등탑에 불씨 바치기(약 15분), 예제는 나이 확인·약관 → 직업 → 튜토리얼 → 자동 사냥 → **서버를 꺼서 끊김 화면** 보기 → 다시 켬(약 10분). 화면마다 누르는 것의 크기·12px 미만 글·대비를 재는 스크립트를 돌렸다(대비는 불투명한 바탕 위의 글만 셈. 3D 위 이름표는 셈에서 뺐다).

**스크린샷**: 작업 기록 폴더 `$TEMP/dg-work/uxrev-shots/`(저장소에 넣지 않음). 이름은 `<게임>-<ph|ls|pc|pc19>-<ko|en>-<번호>-<무엇>.png`. 게임은 `ep` 메아리 계약, `db` 등불지기, `sp` 예제. `ph` 폰 세로, `ls` 폰 가로, `pc` 1280×720, `pc19` 1920×1080. (`ep-ph-ko-01`~`13`은 `pointer: coarse` 흉내를 켜기 전의 것: 크기는 폰이지만 틀은 PC 배치를 골랐다. 탑의 화면은 게임 css가 너비로 고르므로 같다.)

**심각도.** **막힘** = 그 길로는 더 못 간다 / **큰 불편** = 대부분의 사람이 걸리거나 잘못 누른다 / **작은 불편** = 알아채면 넘어간다 / **다듬기** = 상용 수준과의 차이.
**몫.** **틀** = `engine/client/`(모든 게임이 같이 겪는다) / **게임** = `games/<게임>/client/` / **A·B** = 지금 만드는 묶음이 다룰 것.

### 3.2 제안: 토큰을 한 곳에 (`engine/client/tokens.css`, style.css 맨 앞)

게임은 값만 덮어쓴다. 모드·화면마다 다른 분위기는 `body[data-mode="tower"] { --c-surface: …; }`처럼 **같은 토큰을 덮어써서** 틀의 창까지 함께 바뀌게 한다.

**색** (역할 이름. 지금 변수는 별칭으로 남겨 게임을 깨지 않는다)

| 토큰 | 뜻 | 지금 변수 |
|---|---|---|
| `--c-bg` | 문서 바탕 | `--sky` |
| `--c-surface` / `--c-surface-rgb` | 창 바탕(불투명) | `--ink`, `--ink-rgb` |
| `--c-surface-2` | 창 안의 칸·줄 바탕 | (생 색 `rgba(255,255,255,.04)`) |
| `--c-overlay` | 화면을 덮는 막 | `--cover-rgb` |
| `--c-line` / `--c-line-strong` | 테두리 / 고른 테두리 | `--line` |
| `--c-text` / `--c-text-2` / `--c-text-3` | 본문 / 보조(4.5:1 이상) / 흐림(비활성만, 3:1) | `--fg`, `--dim` |
| `--c-accent` / `--c-on-accent` | 주 행동(금빛) | `--gold`, `--on-gold` |
| `--c-good` `--c-bad` `--c-warn` `--c-info` | 상태 | `--good`, `--bad`, (없음), `--ally` |
| `--c-hp` `--c-xp` `--c-mp` | 막대 | `--hp`, `--xp` |
| `--rar-0` … `--rar-5` | **등급 색 표 하나**(목록 테두리·뽑기 연출·이름표·장비 줄이 함께). 지금 `.mrow.rar1~3`(장비), `--rc`(영웅), `RARITIES.color`(3D 고리)가 따로 | — |

규칙: 글자와 바탕의 대비 4.5:1(18px 이상·굵은 14px은 3:1), 등급·상태는 **색 + 모양**(테두리 두께·별·그림)으로.

**글자 크기 단계** (폰 기준, 설정의 배율이 곱해진다)

| 토큰 | 크기/줄 높이 | 쓰임 |
|---|---|---|

| `--fs-sm` | 13/18 | 설명(`.note`)·보조 |
| `--fs-md` | 15/22 | 본문·목록 이름·단추 |

### 3.3 단추 종류 (클래스 넷 + 크기 둘)

| 종류 | 모양 | 쓰임 | 한 화면에 |
|---|---|---|---|
| `.btn-primary` | `--c-accent` 채움, 굵게 | 그 화면의 **한** 다음 행동(모험·다음 단계·뽑기·받기) | 하나(많아야 둘) |
| `.btn-secondary` | `--c-surface-2` 채움 + `--c-line` 테두리 | 다른 행동(다시·홈·자세히) | 여럿 |
| `.btn-ghost` | 테두리·채움 없음, `--c-text-2` | 덜 중요한 것(건너뛰기·닫기 글자) | 여럿 |

토글(자동 진행·자동 사냥·설정 켬/끔)은 단추가 아니라 **스위치 모양**(`.toggle[aria-pressed]`) 하나로. 탭은 `.tabs > button[aria-selected]` 하나로(메뉴 탭·대화 탭·거래소 탭이 지금 셋).

### 3.4 누르는 범위

- `@media (pointer: coarse)`에서 `button, [role=button], select, a.btn`의 `min-height: 44px; min-width: 44px`를 틀이 한 곳에서. 보이는 모양을 작게 두어야 하는 것(대화 탭·별·작은 아이콘)은 `::after { inset: -8px }`로 누르는 범위만 넓힌다.
- 누르는 것끼리 간격 8px 이상(오누름 방지). 튜토리얼 '건너뛰기'처럼 되돌리기 어려운 것은 엄지 자리 밖에.
- 화면 시험(틀의 `engine/test/`)에 '보이는 단추가 눌리는가(1절 1번)·44px'를 폰 크기에서 검사하는 항목.

### 3.5 피드백과 상태

| 상태 | 모양 |
|---|---|
| 눌림 `:active` | `scale(.96)` + 밝기 .9, 80ms. 소리 설정이 켜져 있으면 짧은 '톡' |
| 보냄(서버 응답 기다림) | 단추 흐림 + 작은 돌림, 응답(성공·실패 안내)이 오면 풀림. 2초가 넘으면 '다시 시도' |
| 못 함(모자람) | 흐림 + **단추 아래 이유 한 줄**('조각 78 / 100'), 누르면 이유를 흘러가는 알림으로 |
| 이미 함 | 체크 표시 + 글 '받음', 흐림 없이 낮은 대비 |
| 쿨다운 | 지금처럼 아래에서 차오르는 막(좋다) |
| 성공 연출 | 받은 것이 재화 줄로 날아가는 0.4초(재화 줄은 A), 레벨 업·퀘스트 완료·첫 깸은 가운데 알림 + 빛살 |

**움직임 시간**: `--dur-fast 120ms`(눌림·토글) · `--dur-base 200ms`(창 열기·탭 바꾸기) · `--dur-slow 350ms`(화면 바꾸기·결과 창) · `--dur-reward 600ms`(보상 연출). 곡선은 들어올 때 `cubic-bezier(.2,.8,.2,1)`, 나갈 때 `ease-in` 하나씩. `prefers-reduced-motion`이면 모두 0~50ms(지금의 규칙을 토큰으로 옮김).

### 3.6 정보 구조 (메뉴)

메뉴 탭이 메아리 계약 탑에서 열다섯, 등불지기 아홉. 상용 모바일은 아래 띠 5~6칸 + 각 칸 안의 하위 탭이다. 틀의 `addMenuTab`에 **묶음(`group`)**을 더해: '성장(장비·성장·메아리·편성)', '모으기(뽑기·확률·도감)', '활동(일일·시즌·업적·이벤트)', '소식(우편·친구·길드·순위)', '설정(설정·기기)'. 폰에서는 묶음이 한 줄(5칸), 고르면 하위 탭이 그 아래 한 줄. 홈 키트(B)가 그 묶음을 아래 띠로 쓴다.

### 3.7 빈 상태·오류 상태·로딩의 틀

- **빈 상태 부품** `emptyState({ icon, text, action })`: 그림 하나 + 한 줄 + 다음 행동 단추. 거래소 '올라온 물건이 없습니다' → '[내 물건 올리기]', 친구 0명 → '[이름으로 요청]', 뽑기 기록 없음 → '[1번 뽑기]'.
- **오류**: 서버의 실패 안내(`msg`)를 흘러가는 알림으로만 내지 말고, 누른 단추 곁에 붉은 한 줄(지금 장비 강화 줄이 하는 방식 `.mrow.fail`을 일반화).
- **끊김**: 2.3절 예제의 끊김 행.
- **로딩**: 접속 화면의 진행 막대(있음)에 '무엇을 받는 중'과 0.5초 넘는 서버 응답의 단추 상태(3.5).

### 3.8 접근성 최소 목록

대비 4.5:1(3.2의 `--c-text-3`은 비활성만), 색만으로 가르지 않기, `.banner`·결과 창에 `aria-live="polite"`, 창(`#menu`·결과·확인)에 `role="dialog" aria-modal` + 초점을 창 안에, 닫으면 연 단추로 초점 되돌리기, Esc·뒤로(A)가 창을 먼저 닫기, 설정의 글자 크기가 **모든** 글(3D 이름표 포함)에 먹기, 움직임 줄이기(있음).
