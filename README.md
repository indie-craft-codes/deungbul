# 등불지기 (검증판)

브라우저에서 도는 쿼터뷰 로우폴리 MMORPG의 검증판. 지금 되는 것:

- 접속하면 무작위 이름으로 바로 들어가고, 화면 왼쪽 위의 이름을 눌러 바꾼다.
- 서로 보이고, 대화하고, 몬스터를 잡아 경험치와 불씨를 얻는다.
- 등탑 가까이에서 불씨를 바친다. 등탑 밝기(어스름, 보통, 환함)와 주민 되돌리기는 서버 전체가 함께 채운다.
- 월드는 두 구역이다: 서쪽의 등불 들판(첫불 마을)과 동쪽의 잿빛 숲. 구역마다 등탑이 있고, 잿빛 숲의 등탑은 꺼진 채로 시작해서 모두가 불씨를 바쳐 밝혀야 한다. 밝히면 그 숲에서 쓰러졌을 때 그곳에서 다시 일어난다.
- 잿빛 숲 깊은 곳에 필드 보스 '잿빛 트롤'이 있다. 맞서는 사람이 늘수록 체력이 늘고, 붉은 고리로 예고한 뒤 주변을 내려친다. 쓰러뜨리면 함께 싸운 모두가 보상을 받고, 5분 뒤에 다시 나타난다.
- 직업은 전사와 궁수 두 가지다. 처음 접속하면 고르고, 등탑 가까이에서 바꿀 수 있다.
- 직업은 전사, 궁수, 마법사 셋이다. 마법사는 체력이 가장 적지만 서리로 적을 느리게 하고 치유의 빛으로 곁의 사람까지 살린다.
- 제작: 잿빛 숲의 몬스터가 재료(질긴 가죽, 쇳조각, 잿빛 핵)를 떨어뜨린다. 대장장이 브람이 돌아오면 그 곁에서 재료와 골드로 등불검을 싸게 만들거나, 제작으로만 얻는 잿불검을 만든다 (`shared/content/craft.ts`, `server/game/systems/craft.ts`).
- 파티: 다른 사람을 누르면 뜨는 단추로 초대한다(최대 4명). 파티원이 잡은 몬스터의 보상(경험치, 불씨, 골드, 재료, 퀘스트 진행)을 곁에 있는 파티원 모두가 받는다. 파티원의 체력이 내 정보 아래에 보이고 이름표가 하늘색으로 바뀐다 (`server/game/systems/party.ts`).
- 운영 기본기: 대화의 금칙어는 별표로 가려지고, 금칙어가 든 이름은 쓸 수 없다. 다른 사람을 누르면 대화 차단(내 화면에서만)과 신고를 할 수 있다. 신고는 상대의 최근 대화와 함께 저장소에 기록만 하고, 제재는 사람이 보고 정한다 (`server/net/moderation.ts`).
- 메인 퀘스트 1~4장이 처음 접속한 사람에게 할 일을 차례로 알려 준다. 3장은 잿빛 숲의 등탑을 켜고 잿빛 트롤까지 이끌고, 4장(등탑지기 할멈)은 안개 습격을 함께 막아 내는 것으로 끝난다. 목적지는 빛기둥과 화살표로 표시되고, 퀘스트 창을 누르거나 F 키를 누르면 목적지까지 걸어간다 (도착한 뒤의 전투는 직접 한다).
- 던전 (`systems/dungeon.ts`, 내용은 `shared/content/dungeons.ts`): 잿빛 숲 등탑 옆의 문에서 '잿빛 지하묘'로 들어간다. 레벨 8부터, 하루 3번, 제한 시간 10분.
  - 들어간 사람과 그 파티만의 인스턴스가 생긴다. 같은 지형을 여러 무리가 동시에 쓰지만 층(`Ent.layer`)이 달라 서로 보이지 않고 싸우지 않는다.
  - 무리 넷과 우두머리(지하묘의 주인)가 있고, 잡은 몬스터는 다시 나오지 않는다. 우두머리를 잡으면 안에 있는 모두가 우편 보상과 희귀 이상의 장비를 받고 30초 뒤 문 앞으로 나온다.
  - 안에서 쓰러지면 던전 입구에서 일어난다. 제한 시간을 넘기거나 모두 나가면 인스턴스가 사라진다. 접속이 끊기면 문 앞으로 나온 뒤에 저장된다.
  - 지역(`shared/content/map.ts`의 `AREAS`)은 서로 떨어져 있어 걸어서 넘을 수 없고, 길찾기 격자는 모든 지역을 덮는다. 던전을 더하려면 `AREAS`에 네모를, `DUNGEONS`에 정의를, 언어 파일에 이름을 더한다.
- 장비는 모두 낱개다 (`systems/gear.ts`): 무기·갑옷·반지·목걸이·부적 다섯 칸. 상점에서 사거나 대장간에서 만든 무기·갑옷은 옵션 없는 기본 장비로 가방에 들어와 바로 끼고, 몬스터가 떨어뜨린 것은 등급에 따라 옵션이 붙는다. 무기와 갑옷을 강화하면 기본 수치(공격 피해, 받는 피해 감소)도 단계마다 10%씩 커진다. 들고 있는 무기는 빼거나 팔 수 없다(다른 무기를 끼면 바뀐다). 예전에 저장된 캐릭터는 접속할 때 들고 있던 무기와 갑옷이 기본 장비로 바뀐다.
- 성장의 틀 (메뉴 단추나 M 키. 수치는 모두 `shared/content/growth.ts`의 잠정값이다):
  - 드롭 장비 (`systems/gear.ts`): 몬스터가 6% 확률로(보스는 반드시) 무기·갑옷·반지·목걸이·부적 가운데 하나를 떨어뜨린다. 등급 네 가지(옵션 1~4개), 옵션은 공격 피해·받는 피해·치명타·체력 중에서 무작위. 끼기, 빼기, 팔기, 강화(+10까지, 실패해도 골드만 든다).
  - 우편 (`systems/mail.ts`): 보상을 우편으로 보내 두면 열어서 받는다. 새 보상은 `g.mail.send()`만 부르면 된다.
  - 방치 보상 (`systems/idle.ts`): 10분 이상 접속하지 않으면 그 시간만큼(최대 8시간) 골드·경험치·불씨가 우편으로 온다. 자리 비움 자동 사냥으로 서버가 대신 사냥한 시간은 들지 않는다.
  - 일일 임무와 출석 (`systems/daily.ts`): 임무 세 가지(처치, 바치기, 강화)의 진행을 세고 채우면 보상이 우편으로 온다. 그날 첫 접속에 출석 보상(7일 주기)이 온다.
  - 순위 (`systems/rank.ts`): 전투력(레벨, 무기·갑옷 등급, 낀 드롭 장비)으로 줄을 세운다. 월드와 함께 저장한다.
  - 시스템이 캐릭터에 저장할 것은 `g.saves`에 등록한다 (`PlayerSave.ext`). 특정 플레이어에게만 보낼 메시지는 `g.out`에 넣는다.
- 타격감 (`client/src/fx.ts`): 맞는 순간 모델이 하얗게 번쩍이고 뒤로 움찔하며, 맞은 자리에서 불티가 튄다. 내가 때리거나 맞을 때는 화면이 살짝 흔들리고(치명타는 더 크게), 남의 싸움은 작게 보인다. 화살과 마법은 날아가 닿는 순간에 터진다. 쓰러지는 몬스터는 먼지를 흩뿌린다. 기기의 '동작 줄이기' 설정이 켜져 있으면 화면은 흔들리지 않는다. 전부 화면 연출이고 서버 규칙은 그대로다.
- 다시 접속하면 마지막으로 있던 자리에서 시작한다 (자리와 자동 사냥 켬 여부를 캐릭터와 함께 저장한다). 서버를 다시 띄워 자리 비움 사냥이 끊겼어도, 돌아오면 그 자리에서 자동 사냥이 켜진 채로 이어진다. 쓰러졌을 때만 등탑 앞에서 일어난다.
- 잿빛 숲 등탑 곁에도 상인이 선다 (`shared/content/items.ts`의 `SHOPS`). 파는 물건은 첫불 마을과 같다. 상인을 더하려면 `SHOPS`에 한 줄 더한다.
- 자리 비움 자동 사냥: 자동 사냥을 켠 채 접속이 끊기면(창을 닫음, 폰 화면이 꺼짐) 캐릭터가 월드에 남아 서버가 이어서 사냥한다 (`server/game/systems/away.ts`). 다시 접속하면 그 캐릭터를 그대로 이어받고 자동 사냥도 켜진 채이며, 그동안 얻은 불씨와 골드를 알려 준다. 쓰러지면 등탑에서 일어나 자리를 비운 곳으로 돌아간다. 최대 8시간(`AWAY_MAX_S`)이 지나면 저장하고 나간다. 서버를 다시 띄우면 저장만 남고 사냥은 이어지지 않는다. 직접 움직여 자동 사냥이 꺼진 상태로 나가면 평소처럼 나간다.
- 자동 사냥: 기술 단추 위의 '자동 사냥' 단추나 R 키로 켜고 끈다. 가까운(40m 안) 몬스터를 골라 공격하고, 기술과 회복, 물약을 알아서 쓴다. 직접 움직이거나 멈추면 꺼진다. 클라이언트가 사람과 같은 명령을 보내는 방식이라 서버 규칙은 그대로다. 테스트 편의용으로 넣었고, 출시판에 둘지는 정하지 않았다.
- 장비는 무기와 갑옷 두 칸이다. 갑옷은 받는 피해를 줄인다: 가죽 갑옷(상점 80골드, -12%), 쇠 갑옷(-24%, 브람이 돌아온 뒤 상점 240골드 또는 대장간에서 쇳조각 5·질긴 가죽 6·60골드). 사거나 만들면 바로 갈아입고, 더 낮은 등급은 살 수 없다. 입으면 겉모습도 바뀐다: 가죽 갑옷은 갈색 가슴받이와 허리띠, 쇠 갑옷은 회색 가슴받이에 어깨받이가 붙고, 다른 사람에게도 그렇게 보인다.
- 가방: 내 정보 창의 '가방' 단추나 B 키로 연다. 든 무기, 입은 갑옷, 물약, 제작 재료 수량을 어디서나 볼 수 있다.
- 작은 손질: 같은 알림 문장은 떠 있는 동안 다시 쌓이지 않는다. 신고는 한 번 더 눌러야 접수된다. 직업 바꾸기 창에 지금 직업이 표시된다. 다음 습격 안내에 내일인지와 하루 중 열리는 시간대가 함께 나온다. 장을 마쳤는데 그 주민이 아직 돌아오지 않았으면 완료 알림에 되돌리는 방법이 붙는다.
- 불씨는 1개, 5개, 전부 단위로 바치거나 보탤 수 있다 (가진 것보다 많이 고르면 가진 만큼만).
- 미니맵 (PC 전용, 오른쪽 아래): 나를 가운데에 두고 주변 70m를 화면과 같은 방향으로 그린다. 등탑(네모, 꺼져 있으면 회색), 퀘스트 목적지(고리), 파티원은 범위 밖이어도 가장자리에 붙어서 방향을 알려 준다. 폰에서는 자리가 없어 숨기고 '마을로' 단추로 대신한다.
- 이름표가 겹치면 가까운 쪽부터 놓고 나머지를 위로 밀어 올린다. 피해 숫자는 좌우로 번갈아 벌어져 뜬다 (여럿이 한 점에 몰리는 보스전에서 읽을 수 있게).
- 영어 화면 손질: 짧은 숫자 표시가 낱말 중간에서 끊기지 않게 했고, 길어서 넘치던 문구(조작 안내, 기술 이름, 습격 안내)를 줄였고, 차단·신고 안내 문장을 다듬었다.
- 등탑이 이미 가장 밝아도 불씨를 바칠 수 있다 (한 번에 5개까지). 밝기는 오르지 않지만 기여와 퀘스트에는 세어진다. 등탑이 가득 찬 서버에 새로 온 사람이 '등탑에 바치기' 단계에서 막히지 않게 하려는 것이다.
- 마을로: '마을로' 단추나 H 키를 누르면 첫불 마을 등탑 앞까지 걸어간다 (물약 보충, 불씨 바치기).
- 폰 화면: 가로에서는 대화창이 조이스틱과 기술 단추 사이 아래에 두 줄로 놓이고, 등탑·상점·대장간 창이 열려 있는 동안 퀘스트는 한 줄로 줄어 대화창 위에 남는다. 세로에서는 창의 설명 글을 빼서 퀘스트와 대화가 함께 보인다. 홈 화면에 추가하면 주소창 없이 전체 화면으로 열린다.
- 남의 입장·퇴장 소식은 대화창에 쓰지 않는다. 바칠 불씨가 없으면 퀘스트 창이 몬스터를 잡아 모으라고 알려 준다.
- 집에서 멀리 끌려 나온 몬스터는 집에 도착할 때까지 아무도 쫓지 않는다 (돌아서자마자 다시 대상을 잡아 얼어붙던 문제를 막는다).
- 몬스터를 잡으면 골드도 얻는다. 마을의 길 상인에게서 무기와 물약을 산다. 주민이 돌아오면 상점 물건이 늘어난다.
- 등탑지기 할멈이 돌아오면 등탑에 '오늘의 등탑지기' 명단이 걸리고, 지금까지 바친 불씨에 따라 기여 단계 보상(골드)을 받는다.
- 접속을 끊고 쉬면 휴식 보너스가 쌓여서, 다음에 잡는 몬스터의 경험치를 2배로 받는다 (등불 맡기기).
- 저녁 8~11시 정각마다 안개 습격이 온다. 막으면 밝기가 오르고, 못 막으면 내려간다(-10). 등탑 근처에 사람이 없으면 열리지 않고, 적의 수는 봇을 뺀 사람 수를 따른다. 습격으로 온 적은 이름 앞에 '안개'가 붙는다.
- 알림은 세 곳으로 나뉜다: 놓치면 안 되는 소식은 가운데 알림, 방금 한 일의 결과는 잠깐 떴다 사라지는 한 줄, 대화창에는 사람들의 말과 큰 소식만 남는다 (`client/src/hud/notify.ts`).
- 캐릭터와 등탑 상태는 `data/game.db`(SQLite)에 저장되어 서버를 다시 켜도 남는다.
- 한국어와 영어를 지원한다. 브라우저 언어를 따르고, 화면에서 바꿀 수 있다.

계정은 아직 없다. 브라우저가 간직하는 비밀 값(토큰)으로 캐릭터를 이어받으므로, 브라우저 저장소를 지우거나 다른 기기에서 들어오면 새 캐릭터가 된다.

## 실행

```
npm install
npm run dev        # 개발: 서버(3001) + 클라이언트(5173), 파일을 고치면 바로 반영
```

브라우저 창 두 개에서 http://localhost:5173 을 연다.

빌드본으로 한 포트에서 돌리려면:

```
npm run build
npm start          # http://localhost:3001
```

환경 변수 (PowerShell은 `$env:BOTS=20; npm start`):

| 변수 | 뜻 |
|---|---|
| `PORT=3001` | 포트 |
| `BOTS=20` | 돌아다니며 싸우는 봇 수 |
| `DB=경로` 또는 `DB=memory` | 저장 파일. `memory`면 저장하지 않는다 |
| `RAID_EVERY_MIN=5` | 습격을 시각표 대신 5분마다 연다 (확인용) |
| `DEV_SPAWN=-24,24` | 등탑 대신 그 좌표에서 접속한다 |
| `METRICS=10` | 10초마다 서버 지표(틱 시간, 전송 시간, 전송량)를 한 줄로 찍는다 |

- 주소 뒤에 `?lang=en`을 붙이면 그 언어로, `?auto=이름`을 붙이면 처음 접속할 때 그 이름을 쓴다.
- 진행을 초기화하려면 서버를 끄고 `data/` 폴더를 지운다.
- 서버는 Ctrl+C로 끄면 전원과 등탑 상태를 저장하고 종료한다.
- 같은 공유기의 폰에서는 `http://<이 PC의 IP>:3001` 로 접속한다. Windows 방화벽이 포트를 막으면 허용해야 한다.

## 파일럿 배포

지금 쓰는 방식: 화면은 GitHub Pages, 게임 서버는 이 PC(임시 터널).

- 화면 주소(바뀌지 않는다): https://indie-craft-codes.github.io/deungbul-play/
- 켜는 법: 게임 서버를 켜 두고(`npm start`) `npm run pilot`을 돌린다 (`scripts/pilot.mjs`).
  1. 화면을 빌드해 공개용 저장소 `indie-craft-codes/deungbul-play`(빌드 결과만 들어 있다)에 올린다. 소스 저장소 `indie-craft-codes/deungbul`은 비공개다.
  2. cloudflared로 임시 주소(`https://....trycloudflare.com`)를 받는다.
  3. 그 주소를 `server.json`에 적어 함께 올린다. 화면은 접속할 때마다 이 파일을 읽어 서버를 찾는다 (`client/src/net.ts`).
- `npm run pilot` 창을 닫거나 PC를 끄면 외부 접속이 끊긴다. 다시 켜면 임시 주소는 바뀌지만 화면 주소는 그대로라서 폰의 홈 화면 아이콘은 계속 쓸 수 있다. 올린 뒤 반영까지 1~2분 걸린다.
- 무료 요금제에서는 비공개 저장소로 Pages를 쓸 수 없어서 저장소를 둘로 나눴다.
- 저장은 이 PC의 `data/game.db`다.
- 계정이 없다: 브라우저에 저장된 비밀 값으로 캐릭터를 이어받는다. 홈 화면 아이콘으로 연 것과 사파리로 연 것은 저장 공간이 달라 서로 다른 캐릭터가 된다.
- 다른 곳에 올릴 때: 서버가 `dist/`를 직접 내보내므로 Node 호스팅 한 곳이면 화면까지 함께 된다. 화면만 따로 빌드하려면 `VITE_SERVER_URL=wss://서버주소 npm run build`.

## 다른 게임으로 가져갈 때

틀(엔진)과 이 게임의 내용이 나뉘어 있어서, 내용만 갈아 끼우면 이동·전투·자동 사냥·대화·파티·저장·화면 틀을 그대로 쓴다.

- 그대로 쓰는 틀: `server/net`(접속, 스냅샷, 저장 주기), `server/store`, `server/game/game.ts`(명령·훅·보정 통로), 시스템 중 `movement` `combat` `monsters` `players` `party` `shop` `craft` `classes` `bots` `away` `gear` `mail` `idle` `daily` `rank`, `shared/nav.ts` `shared/sim.ts` `shared/world.ts` `shared/protocol.ts`, 클라이언트의 `net` `input` `actions` `auto` `fx` `entities` `hud/*` `i18n`.
- 갈아 끼우는 내용: `shared/content/*` (맵은 `map.ts`, 직업과 기술은 `combat.ts`, 장비·우편·일일 임무의 수치는 `growth.ts`, 몬스터·아이템·제작·퀘스트), 언어 파일, `client/src/scene/models.ts`의 모델.
- 직업의 겉모습도 데이터다 (`ClassDef`의 `hand`, `shot`, `hitColor`): 손에 든 것의 모양, 날아가는 화살·불꽃, 불티 색, 무기 이름(검/활/지팡이)을 코드가 직업 이름으로 가르지 않는다. 새 직업은 `CLASSES`와 언어 파일에만 더한다.
- 서버 시스템은 필요한 것을 생성자에서 스스로 등록한다: 명령(`g.commands`), 사건(`g.on`), 수치 보정(`g.mods`), 주기 처리(`g.ticks`), 캐릭터 저장(`g.saves`), 월드 저장(`g.worldSaves`), 공유 상태(`g.shared`), 개인 메시지(`g.out`). 시스템을 더하거나 뺄 때 `game.ts`에서 고칠 곳은 생성 한 줄뿐이다.
- 클라이언트의 덧붙는 기능은 `client/src/modules.ts`에 init 한 줄을 더하고, 그 안에서 필요한 것을 스스로 등록한다: 서버 메시지(`bus.onMsg`), 매 프레임(`bus.onFrame`), 느린 주기(`bus.onSlow`), 언어 변경(`onLangChange`). `main.ts`의 메시지 처리와 프레임 루프는 고치지 않는다. 가방, 메뉴, 미니맵, 자동 사냥이 이 방식이다.
- 자동 사냥의 판단(무슨 기술을 쓸지, 언제 물약을 마실지)은 `shared/auto.ts`에 한 번만 적혀 있고, 클라이언트의 자동 사냥과 서버의 자리 비움 사냥이 함께 쓴다.
- 기술은 이름이 아니라 효과의 종류(`SkillEffect`: 한 대상 피해, 범위 피해(+느려짐), 회복)로 처리한다. 새 기술은 `SKILL_DEFS`에 한 줄 더하면 서버·자동 사냥·이펙트가 함께 따라온다.
- 이 게임에만 있는 규칙: 시스템 `tower` `raid` `keepers` `quests` `boss`와 화면의 등탑 창. 틀은 등탑을 직접 알지 않는다. 일어나는 자리, 이동 속도, 직업을 바꿀 수 있는 곳, 물건의 잠금, 습격 적이 향하는 곳은 `g.rules`(server/game/game.ts의 `Rules`)를 거치고, 등탑과 습격 시스템이 그 값을 채운다. 등탑이 없는 게임은 이 시스템들을 빼면 기본 규칙(정해진 자리에서 일어남, 기본 속도, 잠금 없음)으로 돈다. 화면 쪽은 건물이 `scene/scenery.ts`, 미니맵 표식이 `hud/marks.ts`에 따로 있어 이 두 파일만 바꾸면 된다. 클라이언트의 이동 속도 예측(`state.ts`의 `stage`)과 등탑 창(`hud/panels.ts`)은 아직 등탑 상태를 직접 읽는다.
- 지역은 여럿일 수 있다(`AREAS`): 들판과 던전이 한 좌표계 안에 떨어져 놓이고 문으로 오간다. 인스턴스는 층(`Ent.layer`)으로 가른다. 채널(같은 들판을 여러 벌 돌리는 것)과 서버를 여러 대로 나누는 구조는 아직 없다.

## 넓히는 방법

**새 기능(서버 시스템)**: `server/game/systems/`에 파일을 만들고 `game.ts`의 생성자에 한 줄 추가한다. 시스템은 생성자에서 필요한 것을 스스로 등록하므로, 그 밖에 고칠 곳은 없다.

| 등록하는 곳 | 쓰임 |
|---|---|
| `g.commands.set('이름', 처리기)` | 플레이어 명령을 받는다. 통신 계층은 고치지 않는다 |
| `g.on('monsterKilled', ...)` | 다른 시스템의 사건에 반응한다 (사건의 목록은 `Hooks`) |
| `g.mods.provide('damage', ...)` | 수치에 보정을 건다 (피해, 받는 피해, 회복, 치명타, 체력, 불씨) |
| `g.ticks.push(fn)` | 틱마다 돈다 |
| `g.saves.push({ name, save, load })` | 캐릭터와 함께 저장한다 (`PlayerSave.ext[name]`) |
| `g.worldSaves.push({ name, save, load })` | 월드와 함께 저장한다 |
| `g.shared.push({ name, state })` | 모두에게 보내는 공유 상태의 한 칸 |
| `g.rules.respawn = ...` 등 | 틀의 기본 규칙을 바꾼다 (일어나는 자리, 속도, 잠금, 습격 적의 목표) |
| `g.notify(p, 종류, 값...)`, `g.announce(...)` | 안내문을 보낸다 |
| `g.out.push({ id, msg })` | 한 사람에게만 메시지를 보낸다 |
| `g.mail.send(p, 종류, 값, 보상)` | 보상을 우편으로 보낸다 |

우편(`systems/mail.ts`)과 일일 임무(`systems/daily.ts`)가 짧은 예다.

**새 기능(클라이언트 화면)**: 파일을 만들고 `client/src/modules.ts`에 init 한 줄을 더한다. init 안에서 `bus.onMsg('종류', ...)`(서버 메시지), `bus.onFrame`, `bus.onSlow`, `onLangChange`에 등록한다. `main.ts`는 고치지 않는다. 메뉴(`hud/menu.ts`)가 예다. 화면에 보이는 문장은 언제나 언어 파일에 넣는다.

**새 직업, 기술**: `shared/content/combat.ts`의 `CLASSES`와 `SKILL_DEFS`에 더하고 언어 파일에 이름을 넣는다. 기술은 효과의 종류(`SkillEffect`: 한 대상 피해, 범위 피해(+느려짐), 회복)로 처리하므로 서버, 자동 사냥, 이펙트가 함께 따라온다. 새 종류의 효과가 필요할 때만 `systems/combat.ts`의 `useSkill`을 고친다. 직업의 겉모습(`hand`, `shot`, `hitColor`)도 `CLASSES`에 적는다. 새로운 손 모양이 필요하면 `scene/models.ts`에 더한다.

**새 던전**: `shared/content/map.ts`의 `AREAS`에 지역을, `shared/content/dungeons.ts`의 `DUNGEONS`에 문·무리·우두머리·보상을 더하고 언어 파일에 이름을 넣는다. 지형(기둥)은 `PILLARS`, 모양은 `scene/scenery.ts`다.

**새 맵, 구역**: `shared/content/map.ts`에서 범위를 넓히고 `TOWERS`, `CLEARINGS`, `SCATTER`에 더한다. `zoneOf`가 좌표를 구역 번호로 바꾼다. 몬스터 무리는 `shared/content/monsters.ts`의 `CAMPS`에, 상인은 `shared/content/items.ts`의 `SHOPS`에 더한다. 건물의 모양은 `scene/scenery.ts`, 미니맵 표식은 `hud/marks.ts`다. 맵은 하나만 가정한다.

**새 퀘스트 장**: `shared/content/quests.ts`의 `QUESTS`에 장을 더하고 언어 파일에 제목과 단계 문장을 넣는다.

**새 아이템**: `shared/content/items.ts`의 `ITEMS`에 더하고 언어 파일에 이름을 넣는다. `needs`에 조건을 적으면 그 조건이 풀린 뒤에(`g.rules.unlocked`) 상점에 들어온다.

**새 드롭 장비 칸, 옵션, 일일 임무, 출석 보상**: `shared/content/growth.ts`의 `GEAR_SLOTS`, `STATS`, `DAILIES`, `ATTEND`에 더하고 언어 파일에 이름을 넣는다. 새 옵션은 `systems/gear.ts`에서 `g.mods.provide`로 수치에 연결한다.

**새 몬스터, 주민**: `shared/content/`에 정의를 더하고, 언어 파일에 이름을 더하고, `client/src/scene/models.ts`에 모양을 더한다. 이름을 빠뜨리면 컴파일이 실패한다.

**새 언어**: `client/src/i18n/`에 `ko.ts`와 같은 모양의 파일을 만들고 `index.ts`의 `LOCALES`에 추가한다. 빠진 문장이 있으면 컴파일이 실패한다.

**새 안내문**: `shared/messages.ts`에 종류를 더하면 모든 언어 파일이 그 문장을 갖춰야 컴파일된다.

**새 테스트**: `test/이름.test.ts`를 만들고 `test/all.ts`의 목록에 더한다.
